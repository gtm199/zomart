FUTURE FEATURES  (not built yet - add these manually, in roughly this order)
=============================================================================

This first build covers the core loop end to end:
  register shop -> browse central catalogue -> add products with own price/stock
  -> scan or search -> bill (cash/UPI/credit) -> stock + customer ledger update
  -> WhatsApp share link -> daily summary.

Everything below was in the master prompt but is intentionally left out of this
first build. Each item says what to add and where it plugs in.


A. PURCHASING AND SUPPLIERS  (phase 5 of the master prompt)
-----------------------------------------------------------
1. Supplier model (shop-owned) + CRUD API   -> new app: apps/suppliers
2. Purchase + PurchaseItem (invoice no., received qty, cost, partial delivery)
   -> new app: apps/purchases. Goods receipt must call
   services/inventory_service.apply_movement(movement_type="purchase") so stock
   stays ledgered. Update ShopProduct.purchase_cost from the invoice.
3. Supplier payments, supplier ledger, outstanding payables (mirror the
   customer ledger in services/customer_service.py).
4. Purchase returns.
5. Batch and expiry tracking (StockBatch model; sell FEFO) + expiry alerts.
6. Stock valuation report (sum stock_qty * purchase_cost per shop).

B. ACCOUNTING AND REPORTS  (phase 6)
------------------------------------
1. Expense model + categories (rent, salary, electricity...) -> apps/expenses.
2. Net profit = gross profit - expenses (currently only a gross-profit ESTIMATE
   exists in services/report_service.py; it is NOT net profit).
3. Date-range reports: sales by product/category, top sellers, slow movers,
   cash vs UPI, receivables ageing, payables.
4. Daily cash close / cash drawer reconciliation.
5. Optional double-entry journal (AccountingEntry) - if added, enforce that
   every posted entry balances (debits == credits) inside the same DB transaction.
6. Export to CSV/XLSX/PDF.
7. GST: verify current Indian GST rules with a CA before adding formal tax
   invoices, HSN summaries or GSTR export. The current code only stores a tax
   rate and treats prices as tax-inclusive; it is NOT a GST-compliant invoice.

C. WHATSAPP  (phase 4, full version)

To add:

KNOWN SIMPLIFICATIONS IN THE CURRENT BUILD
------------------------------------------
- Stock is a running balance on ShopProduct changed only through
  inventory_service (every change writes a StockMovement). There is no
  separate batch/expiry layer yet.
- Prices are treated as tax-inclusive; tax is split out for display/reports only.
- Purchase cost is a single "latest cost" per product, not FIFO/average cost.
- "Gross profit" is an estimate and ignores expenses.
- Token auth does not expire until logout.
- The mobile app has no offline queue yet; it needs internet for every action.
- Subscription expiry makes a shop read-only after the grace period; it never
  deletes data.
